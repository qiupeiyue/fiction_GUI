## 对齐结论（1.2.2 的实现规格，2026-10-15）

### 数据（拓扑数据存在**类别**上，一律不碰卡片自己的 `parentId`——那是势力在用的字段）
- 类别：`cat.tree = { feature: bool, nodes: { [entryId]: { row, parent } } }`
  - `row`：0 起，显示成 `F0 / F1 / F2…`；`parent`：**树节点自己这个对象里的**父节点 entryId，`""` ＝ 悬空（没有父级）
  - **卡片上不加任何拓扑字段**（既不是 `en.parentId`，也不新开 `en.tree*`）：树和势力两套层级彻底分开，谁都别去读对方的数据
  - 节点与卡片 **1:1**；「树里没有这张卡」＝它左侧列表里的普通卡片，不存在别的标记
- 因此这几条规则天然成立：**复制**的卡不带节点；**合并**后只留主体卡的节点（被并掉那些卡的节点删掉）；**换类别**＝把这张卡的节点连同它下方子树的节点一起删掉（卡片全留着）。**分组**与拓扑无关。
- 追加功能开关：`cat.tree.feature`，和雷达图同一栏「追加功能：☑ 雷达图 ☑ 树型拓扑」，同样是**草稿-保存**语义。
- 可勾的类别：物品 / 名词 / 装备 / 技能树（默认勾）/ 用户新建的类别；**纪年、地点、势力不给这一栏**（地点以后要和地图栏排布再议）。

### 技能树（默认自带的词条种类）
- `defaultCategories()` 里加一条：kind `skill`、名字「技能树」、图标 🔧、grid 布局、默认字段 `类型 / 对象 / 效果 / 前置条件 / 简介`；**不锁**（可改名 / 删除 / 换位）。
- 卡片美术和其它词条种类完全一样；**卡面不加「所属」面包屑**。

### 拓扑栏
- 和「地点→地图栏」同一套形态：设定档案里 `.entry-split` 右栏（`#pane-handle-tree` + `#tree-pane`），可折叠、可拖宽；显示条件＝当前类别勾了树型拓扑。
  **美术照地图栏**：抬头「拓扑」+ 一条细底线，下面**不要亮底圆角方块**（内容直接写在底色上），F 标签小字压暗、每行的「＋」是极简的小虚线框。
- 初始什么都不画，只有 F0 行 + 一个「＋」空节点（可把卡片拖上去，也可点它加卡片）。F0 可以有多张卡（多棵树）。
  「＋」放在每行 F 标签的**右边**（每行都有，永远看得见），点它＝列这一类里「还没进树的卡片」+ 一个「新建卡片」入口；
  没有可加的卡时**不显示任何说明文字**（用户 2026-10-15）。默认栏宽 408px。
- 从上往下一行一个层级（语言无关的 `F0/F1/…`），节点只写名字（固定 96px 宽、名字长了省略）；**悬浮气泡＝名字 + 有值的字段 + 关联人物**。
- **一棵树一个色相，层级做渐变**：按根节点顺序取色板当色相；**这棵树里行号最大的那一层（FN）固定是最深的颜色**
  （往面板底色压 **80%**，`TREE_TONE_MAX`），根那一层最浅（原色**再掺 22% 白**，`TREE_TONE_LIGHT`），中间按 `(row-最浅)/(最深-最浅)` **均分**
  —— 树深树浅都会铺满这段渐变，不会早早压到上限就变平（`treeToneOf()` / `treeToneSpanOf()`）。
  色只画在节点**左侧一条细边**和它那几条连线上
  （`--tree-tone`），卡片本身还是程序那套深色小卡，不刺眼。
- **节点底色＝层级渐变**（`--tree-bg` = `treePlateOf()`）：F0 是一块明显带色的浅底（该层颜色压暗 35%），
  越往下压得越狠，**最下面那一层（FN）接近黑色**（该层颜色压暗 92%，固定值）；有图的卡片照旧把图铺在这个底色之上。
- **连线不跟层级渐变**（用户 2026-10-15）：一棵树就一个固定颜色（`treeEdgeToneOf()`，用这棵树的基础色）。
- **卡片上传过图片的，节点底色就用那张图**（和条目卡面同一套处理：铺满 + 20% 透明 + 轻微模糊 + 放大一点，`span.tree-node-bg`），名字压在上面。
- **连线是「父节点底边 → 子节点顶边」的直线、不折**（用户 2026-10-15：折线在多列多行里会和别的线重合、看着像连错人）；
  同一个父节点的几条线从它底边**不同的点**出发（按子节点左右顺序摊开），不会先叠在一起再分开。
- **布局＝每棵树占自己的一段横向区域**（子节点从父节点下面开始排、父节点坐在自己子节点的正中间；树与树之间空一格）：
  线不会穿过别的节点、同一棵树里的线也不互相重叠（超宽就横向滚动，允许跨行连线）。
  只有一个子节点的链会排成一条笔直的竖线（子节点的期望位置＝父节点那儿，不会甩到这一行最左边）。
- **不做自动压缩空层级**（用户 2026-10-15 明确）：关联 / 改父级之后**行号一律不动**（父子之间空着的行保留），
  自动排的只有左右位置。只有「子级行号 ≤ 父级行号」这种不合法的情况才会把子树往下推到父级 +1。
- **对子节点的操作不许改动上级节点**（拖行号 / 改父级 / 取消父级都只动自己和自己的子树）：用例 `t_skill_tree_child_safe`
- 双击节点＝打开卡片信息；单击＝选中；**Ctrl/⌘ 点加选、点空白清空**；不做 Shift 连选。
- 批量模式（用户 2026-10-16）：抬头**最右边一颗「批量」**，点了才在它左边出现「已选 N / 关联到… / 删除节点」，
  那颗按钮同时变成「**退出**」；**Ctrl/⌘/Shift 点节点＝多选并且自动进批量**；**Ctrl+A＝全选树上的节点（再按＝取消）**；
  **Esc＝退出批量**（有弹窗 / 右键菜单时 Esc 归它们）。批量条和标题**同一行**，不再单独占一行。
- 批量「关联到…」（**2026-10-16 改版**）＝和单节点那套一样**进入监听状态**：点树上的哪个节点，勾选的这一批就挂到它下面，
  **点一下就完成、不用 Enter**，Esc 退出；**不能挂的节点（勾中的自己 / 它们的整棵子树）灰掉禁用**、点不动也不退出监听。
  不再弹「输入框 + 候选下拉」的面板（原来那个面板已删）——**候选就是树上的节点**，没进树的卡点不到、当不了父级。
  （**2026-10-16 用户确认：就这样，不用支持「没进树的卡」当父级**。）

### 拖拽与节点操作
- 从左侧列表拖卡片进栏：落到**节点上**＝成为它的子级；落到**某一行空白**＝在该行生成一个**悬空**节点（允许「在第 N 行但没有父级」）。
- 拖树上的节点：连同下方子树一起走；落到节点上＝改父级；落到行空白＝改行号。
- 单选右键菜单：**编辑 / 替换… / 关联到… / 删除节点**
  - 2026-10-16 追加两项（在「关联到…」下面）：**左移 / 右移**＝和左右相邻的那棵树换**显示位置**
    （只换横向次序存进 `cat.tree.order`，层级 / 父子关系 / 树里的拓扑 / 卡片自己的次序一律不动，颜色也跟着树走不跟着位置走）；
    最左那棵树「左移」灰、最右那棵树「右移」灰；点灰掉的不响应也不关菜单；可撤销。用例 `t_skill_tree_order`。
  - **悬空**（2026-10-16 由「无（悬空）」改名）：去掉这个节点和上级的拓扑关系，只动它自己（下级照旧挂着、卡片不删）。
    批量条＝「已选 N / **悬空** / 关联到… / 删除节点」，悬空在最左、勾选的节点都没上级时灰掉。用例 `t_skill_tree_detach`。
  - **左移 / 右移 / 悬空 之后都要跑 AUTO-TIDY**：`treeNormalize` 规整 → 重新横排 + 重画连线（行号不动）。
  - 替换：输入框 + 匹配下拉（程序自带面板）。b 不在树里 → 直接替换；b 在树里且**不是** A 的祖先 → b 连它的子树移植到 A 的位置；b 是 A 的祖先 → 该候选灰色禁用，拖拽同样无效。
  - 关联到…：进入**监听状态** → 点树上的节点即完成（**不用 Enter**），Esc 退出；抬头一行小字「点一个节点完成关联 · Esc 退出」，
    **跟标题同一行**（不换行、不把标题挤折行），单节点流程里那颗「**悬空**」放在**抬头最右边**（＝取消这个节点的上级）。
    **监听中不露出「批量」/「删除节点」**（单节点流程的批量条也一起收起来）——要干别的先按 Esc 结束监听。
    能挂的节点亮起来（`can-link`），**不能挂的（自己 / 自己的整棵子树）灰掉禁用**（`no-link`，点不动、也不退出监听，
    气泡写明原因）。**Enter 不再＝悬空**（2026-10-16 去掉的老毛病）。禁止成环。用例 `t_skill_tree_batch_link`。
  - 删除节点：删掉这个节点 + 它下方的子树节点（**卡片都留着**，可撤销）。
- 多选：**1 个上级节点 + ≥1 个下级节点**时「关联」按钮才亮，否则灰；「删除节点」也在这一排。
- 卡片信息界面：显示父级卡 + 直接子级卡（双击打开）；**界面里不给改层级**。
